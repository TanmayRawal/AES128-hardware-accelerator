AES-128 Image Encryption on FPGA

A High-Performance Hardware-Software Co-Design for Secure Visual Data Transmission

1. Executive Summary

This project implements a complete System-on-Chip (SoC) on the Nexys 4 DDR FPGA platform to encrypt image data using the Advanced Encryption Standard (AES-128). The architecture utilizes a hybrid approach: a MicroBlaze Soft-Core Processor manages system control and data handling, while a Custom AES IP Core handles the computationally intensive cryptographic operations in hardware.

2. System Architecture

The design is based on the AMBA AXI4 Interconnect, the industry-standard bus for FPGA systems. The primary components are:

MicroBlaze CPU

A 32-bit RISC processor that acts as the system controller. It executes C code to manage UART communication and AES control signals.

AES-128 AXI IP

Our custom hardware accelerator. It performs 10 rounds of AES encryption in just 12 clock cycles per block.

AXI BRAM Controller

Provides 8KB of high-speed on-chip memory to store the image pixels and the encrypted results before transmission.

UART Lite IP

The bridge between the FPGA and the host PC, transmitting data at 115,200 baud.

[ PC (Python) ] <--- UART ---> [ UART Lite IP ] <--- AXI Bus ---> [ MicroBlaze ] <---> [ AES IP Core ]

3. Technical Specifications

A. Hardware Details

Attribute Specification
FPGA Device Xilinx Artix-7 (XC7A100T-1CSG324C)
System Clock 25.0 MHz (Optimized for Timing Closure)
Encryption Latency ~480 nanoseconds per 128-bit block
Resource Usage ~2,800 LUTs, ~1,900 Flip-Flops, 2 BRAM Blocks

B. Software Flow (The C Application)

The software running on MicroBlaze performs the following loop:

  • Initialization: Sets up UART and waits for a physical button press (Button C).
  • Data Fetch: Reads a 128-bit block from the Input BRAM.
  • Hardware Call: Writes the 128-bit block to the AES IP registers via Xil_Out32.
  • Wait/Status: Polls the AES Status register until the "Done" bit is set.
  • Result Storage: Reads the 128-bit ciphertext and stores it in the Output BRAM.
  • Transmission: Sends the encrypted bytes over UART to the Python script.

4. The Custom AES-128 IP Core

The AES core was designed in Verilog and wrapped with an AXI4-Lite interface. Key design features include:

  • Combinational Key Expansion: The round keys are expanded in a single clock cycle to minimize latency.
  • Round Logic: Each round performs SubBytes, ShiftRows, MixColumns (for rounds 1-9), and AddRoundKey.
  • Address Map:
    • 0x00: Control Register (Bit 0 starts encryption)
    • 0x04: Status Register (Bit 0 indicates completion)
    • 0x08-0x14: 128-bit Key Registers
    • 0x18-0x24: 128-bit Data Input Registers
    • 0x28-0x34: 128-bit Data Output Registers

5. Design Challenges & Optimization

Critical Optimization

During implementation, we encountered a Timing Violation where the logic paths in the AES key expansion were too long for a 100 MHz clock. Solution: We utilized a clk_wiz (Clock Wizard) to reduce the system clock to 25 MHz. This provided a 40ns period, giving the signals enough time to propagate through the complex AES logic, ensuring 100% stability on hardware.

6. Conclusion

This project successfully demonstrates the power of FPGA Hardware Acceleration. By offloading the AES encryption to a custom IP core, we achieved high-throughput encryption while keeping the system flexible through software control. The end-to-end integration from Python scripts to FPGA logic provides a robust foundation for secure IoT and edge computing applications.
