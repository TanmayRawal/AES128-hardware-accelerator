Implementation of a High-Throughput AES-128 Cryptographic Accelerator on Artix-7 FPGA

Technical Design Report for Nexys 4 DDR Platform
Abstract— This report details the design, implementation, and verification of a hardware-accelerated Advanced Encryption Standard (AES-128) system on a Xilinx Artix-7 FPGA. By leveraging a System-on-Chip (SoC) architecture, we integrate a MicroBlaze soft-core processor with a custom-designed AXI4-Lite AES peripheral. The system achieves high-security image encryption by offloading the computationally intensive Rijndael algorithm to a dedicated hardware datapath, while maintaining control-plane flexibility via C-based firmware. We address critical design constraints, including bus synchronization, memory-mapped I/O addressing, and static timing closure at 25 MHz.

I. Introduction

In modern embedded systems, security is a paramount concern. Software-based encryption often suffers from high latency and power consumption. Field Programmable Gate Arrays (FPGAs) provide a unique platform to implement cryptographic algorithms in parallel hardware, offering significantly higher throughput. This project demonstrates a complete end-to-end encryption pipeline, from raw image capture on a host PC to hardware-accelerated encryption on the Nexys 4 DDR board.

II. Cryptographic Foundation

The system utilizes AES-128, a symmetric-key block cipher. The algorithm operates on a 128-bit state matrix through four distinct stages per round:

  • SubBytes: A non-linear substitution step using a lookup table (S-Box).
  • ShiftRows: A transposition step where the last three rows of the state are shifted cyclically.
  • MixColumns: A linear transformation that provides diffusion across the columns of the state.
  • AddRoundKey: A simple XOR operation between the state and the subkey for that round.

Our hardware IP implements the 10 rounds of AES-128 in a non-pipelined architecture, completing a full encryption in 12 clock cycles.

III. System Architecture & Component Analysis

The system is built using a memory-mapped architecture connected via the AXI4-Lite bus.

1. MicroBlaze Soft-Core Processor: The MicroBlaze is a 32-bit RISC processor. Its role is Orchestration. It reads raw image data from the BRAM, handles the handshake with the AES hardware, and manages the UART communication. It allows us to implement complex logic (like the encryption loop and UART framing) in C, which is much faster to develop than pure Verilog state machines.
2. Custom AES-128 AXI Peripheral: This is the Accelerator. It contains the Verilog implementation of the AES datapath. We wrapped it in an AXI-Lite interface, which allows the CPU to see the AES hardware as a set of memory addresses.

3. AXI BRAM Controller & Block RAM: Used as Local High-Speed Storage. Accessing external DDR RAM is slow and complex. By using on-chip BRAM, the MicroBlaze can read/write pixels with single-cycle latency, preventing the CPU from becoming a bottleneck during the encryption process.
4. AXI UART Lite: The External Interface. It implements the RS-232 protocol to transmit the encrypted image back to the host PC at 115,200 bits per second.

IV. Hardware-Software Interface (The AXI Protocol)

Communication between the CPU and the AES IP follows the AXI4-Lite Handshake. Every write operation involves three phases: 1. Address Phase: The CPU places the address on S_AXI_AWADDR. 2. Data Phase: The CPU places data on S_AXI_WDATA. 3. Response Phase: The IP core acknowledges the write with S_AXI_BRESP. This ensures that no data is lost during the high-speed transfer between the processor and the accelerator.

V. Design Optimization: Static Timing Analysis

One of the major engineering challenges was Timing Closure. The AES algorithm involves deep combinational logic (especially the MixColumns and S-Box transformations). Initially, at 100 MHz, the path delay exceeded the 10ns clock period, causing "Setup Time Violations."

Optimization Strategy: We implemented a Clock Wizard IP to derive a stable 25 MHz clock from the 100 MHz board oscillator. By increasing the clock period to 40ns, we provided sufficient "Slack" for the signals to propagate through the AES IP registers, resulting in a stable hardware implementation that does not crash or produce garbage data.

VI. Verification Methodology

Verification was performed in two stages:

  1. Software Emulation: A Python script using the cryptography library generated a "Golden Reference" ciphertext.
  2. Hardware Execution: The FPGA processed the same image, and the output was compared byte-for-byte against the Golden Reference.

The result was a 100% match, confirming the mathematical accuracy of the Verilog implementation.

VII. Conclusion

This project successfully demonstrates a functional AES-128 accelerator on an Artix-7 FPGA. The use of AXI4-Lite as an interconnect provides a scalable architecture where additional accelerators could be added. The 25 MHz system provides a robust balance between throughput and timing stability, making it an ideal platform for secure image processing applications in embedded environments.
